# 对话界面显示 / 隐藏规则

> 原则（用户原话的问题）："我的界面基本都给用户在聊天界面看到了"。
> 聊天区只给用户看**结论和需要他决策的东西**；过程进右侧 tab，细节进折叠。

## 1. 显示矩阵

| 内容 | 聊天区 | 去处 |
|---|---|---|
| 用户消息 | ✅ 气泡（右） | — |
| Agent 最终回复正文 | ✅ 气泡（左） | — |
| 审批卡 | ✅ 内嵌气泡（保留现有） | Tab 2 同步一份总览 |
| 工具调用摘要行 | ✅ 灰色小行（见 §2） | 详情进 Tab 3 |
| 子 Agent 进展 | ✅ 灰色小字单行 | 详情进 Tab 3 分组 |
| 错误（人话） | ✅ 红色小行 + 可展开 | 堆栈只进 Tab 3 |
| tool_call 原始 JSON | ❌ 永不 | Tab 3（折叠，只读） |
| Agent 内部规划/思考过程 | ❌ 永不 | 转成 Tab 1 的 plan 步骤 |
| 工具结果全文 | ❌ 默认不 | Tab 3 点开展示 / 聊天区"详情"跳转 |
| 记忆写入内容 | ❌ | Tab 4 |
| token/模型信息 | ❌ | Tab 4 + 输入框右上角小字 |

## 2. 工具调用在聊天区的呈现（一行，可展开）

```
🛠️ 执行了 3 个工具 · 详情
```
- 默认只一行灰色小字，不占气泡。
- 点"详情"：展开为紧凑列表（工具人话名 + ✓/✗ + 耗时），每条可再点跳 Tab 3 看参数。
- **禁止**出现：`{"name": "desktop_open_app", "arguments": {...}}` 这种裸 JSON。

## 3. Before / After（拿用户 2026-10-12 截图的两个反例）

### 反例 A：裸 JSON 气泡
Before（当前）：
```
{"name": "desktop_open_app", "arguments": {"app_name": "ClashVerge.exe"}}
[黑框：请确保 'ClashVerge.exe' 的路径正确…]
```
After：
- 聊天区：工具摘要行 `🛠️ 执行了 1 个工具 · 详情`（点开：`打开应用 ClashVerge.exe ✗ 0.8s`）
- 错误人话行：`⚠️ 没找到 ClashVerge.exe，我去桌面快捷方式里找找看`（点开展示完整报错）
- Tab 3：该条目点开可见完整参数 JSON + 完整报错文本。

### 反例 B：内心独白气泡
Before（当前）：
```
明白了，我会尝试通过桌面快捷方式来打开 Clash Verge。
首先，我将列出桌面上的所有可见应用程序窗口名称及位置，以确认…
{"name": "desktop_list_windows", "arguments": {}}
```
After：
- 聊天区：**这段不显示**。对应 plan 步骤进 Tab 1（"通过桌面快捷方式打开 Clash Verge" 进行中），
  工具调用进 Tab 3。
- Agent 气泡只在**最终有结论**时出现，例如：
  `没在桌面找到 Clash Verge 的快捷方式。你方便告诉我它的安装路径吗？`

### 实现规则（给反重力）
- 后端 `run_turn` 返回给前端的消息流里，**区分** `role=assistant`（最终回复，进气泡）
  和 `role=tool` / 中间 reasoning（不进气泡，只发事件进 tab）。
- Prompt 层加约束（`prompts/system-slim.md` 追加一条）：
  "你的思考过程和工具调用由系统单独展示，**不要**在回复正文里复述你的计划、
  不要贴工具调用的 JSON，回复只写用户需要看到的结论和问题。"
- 前端渲染器加白名单：气泡只渲染 `type in (user, assistant_final, approval_card, tool_summary, error_line)`，
  其他类型直接丢给 tab store——**前端兜底**，即使后端漏发事件也不至于把 JSON 倒进聊天区。

## 4. 验收标准
1. 跑任意 3 步以上的任务，全程聊天区无裸 JSON、无内心独白复述。
2. 每个工具调用在 Tab 3 可找到对应条目（含参数、耗时、结果摘要）。
3. 审批卡在聊天区和 Tab 2 双向同步：任一一边点通过，另一边状态同步变更。
4. 刷新页面后聊天记录渲染仍遵守本规则（历史消息里的 tool role 不进气泡）。
