# UI 重设计：布局、右侧 4 Tab、头像实时动画

## 0. 截图里的问题（2026-10-12 用户实拍，逐条）

1. **tool_call 原始 JSON 直接显示在对话气泡里**：
   `{"name": "desktop_open_app", "arguments": {"app_name": "ClashVerge.exe"}}`
   整段裸 JSON 扔给用户——这是 display-rules 要根治的头号问题。
2. **Agent 内心独白外泄**："明白了，我会尝试通过桌面快捷方式来打开…首先，我将列出桌面上
   的所有可见应用程序窗口名称及位置…"——这是 chain-of-thought，不是回复。
3. 右侧只有"待审批/运行中任务"两个死区块 + 一张静态推广卡，无 tab、无展开。
4. 头像（"影"）是静态圆字，无任何状态反馈；用户盯着界面不知道 Agent 在干嘛。
5. 中间一道黑色渲染 artifact（app.js 渲染 bug，顺手修）。

---

## 1. 整体布局（对标 Muse）

```
┌──────────┬──────────────────────────────┬────────────────────┐
│ 导航+会话 │  对话区                       │  右侧 4 Tab         │
│ 列表     │  ┌────────────────────────┐  │  [任务|审批|动态|状态]│
│          │  │ 顶栏:头像(动画)+状态文字 │  │                    │
│          │  ├────────────────────────┤  │  tab 内容区         │
│          │  │                        │  │  (每项可点开展示    │
│          │  │  消息流                │  │   进度详情)         │
│          │  │                        │  │                    │
│          │  ├────────────────────────┤  │                    │
│          │  │ 输入框                 │  │                    │
│          └────────────────────────┘  │                    │
└──────────┴──────────────────────────────┴────────────────────┘
```

- 左栏：保留（会话列表+新建），样式向 Muse 看齐：深色窄栏、圆角会话卡、hover 显示删除。
- 中栏顶栏：**头像 + 实时状态文字**（见 §3），替代现在的纯标题栏。
- 右栏：4 个 tab（见 §2），默认选中"任务"；有待审批时 tab 自动跳"审批"并红点。

## 2. 右侧 4 个 Tab（每个都可点开展示进度详情）

### Tab 1：任务（Plan）
- 内容：本轮 plan 的步骤列表（来自 Planner JSON），每步状态：待执行/进行中/已完成/失败。
- 点开某步：该步的简述、关联的子任务/工具调用（跳转到"动态"对应条目）。
- 空态："暂无任务，直接在下方输入框描述你的需求"。
- 数据源：`plan_update` 事件（见 event-protocol.md）。

### Tab 2：审批（Approvals）
- 内容：待审批队列（现在的审批卡**同时**保留在对话流内嵌——双入口，tab 里是总览）。
- 点开某条：完整参数、风险说明、scope 选项、倒计时；可直接在 tab 里点通过/拒绝
  （与对话内嵌卡双向同步状态）。
- 有新的待审批：tab 自动切换过来 + 红点 badge（现在的🔔逻辑并入此处）。

### Tab 3：动态（Activity）
- 内容：本轮所有工具调用的时间线：`14:02:11  browser_navigate  打开 github.com  ✓ 1.2s`。
- 点开某条：完整参数（折叠的 JSON，只读）、执行结果摘要、"在聊天中查看"跳转。
- 子 Agent：单独分组显示，点开展示它的简报、状态、（完成后）结果摘要。
- 数据源：`tool_call_started` / `tool_call_done` / `subagent_update` 事件。

### Tab 4：状态（Status）
- 内容：
  - 当前模型：`主 Agent: qwen2.5-coder-32b（主） / Agnes Flash（备）`，当前用的是哪个
  - 本轮 token：输入/输出（累计）
  - 记忆写入：本轮写入 MEMORY 的条目（点开展示原文）
  - 连接状态：本地服务正常/模型 API 延迟
- 数据源：`token_usage` / `memory_write` / `agent_state` 事件。

## 3. 头像实时动画 + 状态文字

### 位置
中栏顶栏：圆形头像（保留"影"字或换 Logo）+ 右侧一行状态文字。
头像外圈有一圈状态光环，颜色随状态变。

### 状态机（6 态，全部由 `agent_state` 事件驱动）

| 状态 | 头像动画 | 光环色 | 状态文字示例 |
|---|---|---|---|
| `idle` | 静止 | 灰 | "就绪" |
| `thinking` | 呼吸式缩放（CSS pulse） | 蓝 | "正在思考…" |
| `acting` | 旋转弧光（CSS spin ring） | 绿 | "正在执行：读取文件 src/main.py"（当前工具的人话描述） |
| `awaiting_approval` | 闪烁（blink） | 橙 | "等待你的确认：删除 3 个文件" |
| `error` | 抖动一次 + 红 | 红 | "出错了，正在重试（2/3）…" |
| `done` | 短暂✓弹跳后回 idle | — | "完成"（2 秒后回"就绪"） |

### 人话描述规则
`acting` 的文字**不许**出现 raw 工具名+JSON。映射表（前端常量）：
`file_read` → "正在读取文件 {path}"，`shell_exec` → "正在执行命令 {command前40字}"，
`browser_navigate` → "正在打开网页 {domain}"，`desktop_click` → "正在点击桌面位置"，
未知工具 → "正在执行 {中文动作名}"（ACTION_CN_MAP 已有，复用）。
参数只取最关键的一个字段，其余不显示。

### 实现要点
- 纯 CSS 动画，6 个 class（`avatar-idle/thinking/acting/...`），JS 只做 class 切换——
  不许用 JS 定时器做动画帧。
- 状态文字用 `agent_state.detail` 字段，后端拼好人话，前端只负责显示
  （人话模板放后端 `agent/state_text.py`，中英文一处维护）。
- 防抖：`thinking`↔`acting` 高频切换时，文字更新节流 300ms，动画 class 直接切。

## 4. 对话区渲染（概要，细则见 display-rules.md）

- 用户气泡右，Agent 气泡左——保留。
- Agent 气泡只放：**最终回复正文** + 一行工具摘要（"🛠️ 执行了 3 个工具 · 详情"点开展示）
  + 审批卡（内嵌，保留）。
- raw JSON、内心独白、完整工具结果：永不直接进气泡。
- 子 Agent 进展：在气泡下以灰色小字单行插入（"子 Agent 正在搜索文档…"），不占整气泡。
- 修黑色 artifact：排查 `app.js` 消息渲染的空 `<pre>`/未闭合标签（截图中部黑块）。

## 5. 输入框
- 保留 Shift+Enter 换行 / Enter 发送。
- 新增：输入时右上角显示当前模型（"本次对话将使用 qwen2.5-coder"小字），
  来自 `agent_state` 的 `model` 字段——让用户对"谁在干活"有感知。
- 发送后输入框立即清空+禁用，`done`/`error` 后恢复（防重复提交）。
