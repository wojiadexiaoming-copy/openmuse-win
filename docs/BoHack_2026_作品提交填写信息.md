### 【第 8 项】进化说明 3：坏了怎么回退 *
```text
系统构建了 5 级纵深防御与容灾回退体系，确保在任何单点故障下均能安全可逆地回退：

1. 【模型层：多级 Fallback Chain 自动逐级回退】：
主脑模型遇到网络超时、并发限流（429）、额度耗尽（403）或上下文溢出时，系统按配置顺序自动逐级无损回退（MiniMax-M2.5 -> DeepSeek-V4-Flash -> Qwen3.8-Flash -> Kimi-K3.1-Pro）。若全链异常，自动降级至本地离线模型并告警，绝不静默崩溃。

2. 【热计算层：缓存击穿旁路与自动 FIFO 熔断淘汰】：
热计算缓存设有全局强制旁路开关（use_cache=False）与 60s 软 TTL；一旦检测到写入操作或校验不一致，立即失效并清空当前作用域缓存；单项数据超过 200KB 自动拒绝入内存，总缓存项超 1000 条自动触发 20% FIFO 批量淘汰，发生任何缓存异常瞬时回退至直连执行。

3. 【执行层：子进程沙箱 Watchdog 软硬两级回收】：
所有子任务均在独立 multiprocessing 沙箱运行。若子进程发生死循环、内存超出 512MB 配额或超过最长执行时限，看门狗先发送软中断要求保存状态；若 10 秒内未响应，立即执行操作系统级强杀（SIGKILL）并强制释放桌面全局锁与浏览器写租约，确保主进程与 UI 永不卡死。

4. 【存储层：SQLite WAL 事务原子性与开机断点自愈回退】：
所有任务状态与会话采用 SQLite WAL 模式增量落盘。若遭遇意外断电或强行关机，重启后自动校验最后有效检查点；UI 顶部通过 Resume Bar 提示用户，支持一键选择“继续未完任务”、“回退至上一个已知安全步”或“安全放弃”。

5. 【安全层：移动端高危审批超时自毁熔断】：
微信端推送的审批卡片设有 300s 倒计时保护。若用户在微信中点击“拒绝”或超时未审批，系统自动将当前操作回滚，并持久化记录安全审计日志，拒绝任何未经授权的高危操作。
```
