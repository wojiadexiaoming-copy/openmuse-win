# Skill：Windows 桌面自动化实战规则

> 注入时机：本轮对话涉及 `desktop_*` 工具时，由 ContextBuilder 动态拼接到 system prompt 之后。
> 来源：AlterEgo 桌面 UIA 句柄与桌面特有面架构升级实战规范。

---

## 一、四层交互阶梯策略（铁律）

在操作 Windows 桌面应用时，必须严格遵循以下四层优先级递进：

```
[第一层: UIA Pattern 直调 (Invoke/Toggle/Value)] -> 零光标抢占、精准率 100%、耗时最低
      │ (控件不支持 Pattern 或无 Pattern)
      ▼
[第二层: 短句柄坐标点击 (ref: "c1".."c64")] -> 自动换算控件中心物理屏幕像素，抗 DPI/缩放漂移
      │ (未扫描到控件或需要精确偏移点)
      ▼
[第三层: 截图目测坐标点击 (x, y)] -> 必须携带当前 snapshot_id，严格在 image 范围内取点
      │ (自研引擎/DirectUI/游戏/Flutter无障碍未开启)
      ▼
[第四层: 纯视觉兜底 (Vision Fallback)] -> 借助截图目测坐标与 probe_app 诊断指导完成操作
```

1. **观察后优先用 `ref` 句柄**：每次 `desktop_snapshot` 会在元数据和文本中返回 `c1..c64` 短句柄及对应的控件类型与支持的 Pattern。操作目标控件时，**首选直接传入 `ref="c1"`**！
2. **底层自动 Pattern 直调**：当你使用 `ref` 点击支持 `Invoke`、`Toggle`、`SelectionItem`、`ExpandCollapse` 的控件时，底层会自动通过 COM STA 直调对应接口，**不会瞬移物理鼠标光标**，不干扰物理用户当前视线与光标。

## 二、键盘优先原则（Keyboard-First）

桌面软件的焦点与交互设计高度依赖键盘，**能用键盘快捷键完成的高频动作，优先使用按键，不要费力去点鼠标**：

| 交互意图 | 推荐工具与按键 | 优势说明 |
| :--- | :--- | :--- |
| **关闭弹窗 / 取消选择** | `desktop_press({"key": "esc"})` | 瞬间关闭模态弹窗，无需寻找右上角微小的关闭按钮 |
| **确认对话框 / 提交表单** | `desktop_press({"key": "enter"})` | 默认焦点在确认按钮时直接回车触发 |
| **表单项快速跳转** | `desktop_press({"key": "tab"})` | 下一个输入框/按钮；反向跳转用 `desktop_hotkey({"keys": ["shift", "tab"]})` |
| **关闭当前窗口 / 应用** | `desktop_hotkey({"keys": ["alt", "f4"]})` | 干净关闭进程，避开窗口关闭按钮坐标漂移 |
| **全选 / 复制 / 粘贴** | `desktop_hotkey({"keys": ["ctrl", "a"]})` 等 | 快速处理文档与文本区 |
| **保存文件** | `desktop_hotkey({"keys": ["ctrl", "s"]})` | 触发原生保存操作 |

## 三、中文输入与文本输入规范（铁律）

1. **严禁按键模拟打中文**：绝对禁止通过 `pyautogui.typewrite` 或按键逐字打拼音！在 Windows 下这会调起用户本地安装的搜狗/微软拼音输入法候选框，极高概率产生乱码、错字或吞字。
2. **必须使用 `desktop_type`**：
   - 目标输入框支持 `ValuePattern` 时，底层通过 UIA 接口直接写入文本（无需读写剪贴板）。
   - 目标输入框不支持 `ValuePattern` 时，底层自动通过**无损剪贴板备份与恢复机制**安全粘贴文本，并在 `finally` 块中立即恢复用户原有的剪贴板内容，不污染用户日常复制的数据。
3. **提交与回车**：
   - 只有当原目标明确是“向聊天窗口发送消息”或“向 AI 生成界面提交提示词”，且确认 Enter 为提交键时，才在 `desktop_type` 中传入 `press_enter=True`；
   - 在普通表单、多行文本编辑器或语义不明的场景中，保持 `press_enter=False`，防止误触导致未填完就提交。

## 四、安全与治理面守护机制

1. **物理光标与键盘抢占让出**：
   - 系统内置微秒级 `GetLastInputInfo` 物理输入检测。
   - 当返回 `[桌面已让出]` 时，表示检测到物理用户刚刚移动了鼠标或敲击了键盘（空闲时间 < 2.0s）。自动化已主动暂停并保护现场，**切勿强行重试**。请回复用户：“检测到您正在操作电脑，自动化已暂停；您忙完后请回复‘继续’”。
2. **UAC / Secure Desktop 拦截**：
   - 当遇到 Windows 系统安全桌面（UAC 提权确认、用户凭据提示、Ctrl+Alt+Del 等）时，由于普通用户权限进程无法跨越隔离桌面，系统会返回 `[桌面安全拦截]`。
   - 此时主动引导用户在屏幕上手动点击“是”或授权后回复“继续”，不要尝试暴力穿透。
3. **不可逆高风险操作双重防御**：
   - 若目标控件涉及“彻底删除”、“格式化”、“清空全部”、“注销账号”等不可逆破坏性动作，系统会自动拦截并要求传入 `confirmed=True`。切勿在未经用户明确指示的情况下擅自确认高危破坏操作。

## 五、应用框架诊断与视觉兜底

1. **遇到不响应或无法识别控件时**：
   - 调用 `desktop_probe_app(window_title="目标窗口")` 获取应用诊断报告。
   - 系统会自动判断当前窗口属于 Win32、WPF、UWP、Chromium、Qt 还是无无障碍支持的自研引擎，并给出最佳策略。
2. **Chromium 浏览器重定向**：
   - 若诊断显示为 Chrome/Edge 浏览器，优先切换或建议使用 `browser_*` 系列工具以获得更强劲的 DOM/CDP 级自动化控制。
3. **自绘/游戏无障碍界面视觉兜底**：
   - 若控件树为空，使用 `desktop_screenshot` 观察实际截图像素，按 0..width / 0..height 像素坐标直接调用 `desktop_click(x=..., y=...)`。
